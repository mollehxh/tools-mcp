# tools-mcp 0.1.0 hybrid execution — evidence-scoped draft

This release is not final until the live reboot, power-loss, Windows CI, and
seven-day soak gates recorded below pass. This note deliberately separates
implemented behavior from platform evidence.

## Shipped behavior

- One OAuth-protected ChatGPT MCP endpoint exposes exactly `exec_command`,
  `write_stdin`, `apply_patch`, `skills.list`, and `skills.read`.
- A healthy newest local macOS or Windows worker receives new calls. When no
  local worker is eligible, a persistent isolated VPS workspace is selected
  within the lease deadline. Route-context changes require a fence; calls are
  never replayed after an ambiguous backend loss.
- Refresh-token rotation avoids routine consent. Device and grant revocation
  close active relay authority and stale/disaster restore invalidates prior
  OAuth and worker credentials.
- The VPS workload runs as root inside a bounded rootless Podman container,
  while `/workspace` and `/home/developer` persist independently of its root
  layer. Git is the only supported continuity mechanism between local and VPS
  workspaces.
- Linux VPS releases are deterministic bundles containing gateway, admin,
  runner, rootless-container and supervised deployment assets. Linux is not a
  supported general local-worker package.
- One `tools-mcp` npm command selects the matching native macOS or Windows
  package. After one human-controlled device enrollment and setup, launching
  the bare command fixes the current directory as the workspace; no daily
  relay or certificate arguments are required.
- In the VPS multi-repository workspace, a command `workdir` selects the nearest
  Git repository for that MCP session's project skills. Sibling repositories
  remain separate and stale project handles fail closed after a switch.

## Live evidence obtained

- macOS native launcher/runtime and package gates passed locally.
- ChatGPT discovery, consent, all five tools, and two refresh rotations passed
  against the staging gateway/relay/VPS runner through the account-owned free
  ngrok hostname.
- Rootless container identity, persistence, tool inventory, egress denial,
  process cleanup, byte/inode isolation, PID/OOM enforcement, and bounded-load
  gateway responsiveness passed on the VPS before its first reboot.
- A real reboot changed the boot ID and preserved SQLite, workspace/home hashes,
  every Docker container ID/state, route ownership, and supervised recovery.
  The drill found and fixed inherited rootless Podman pause-namespace failures
  for TUN, procfs, and slirp tmpfs; the deployed preflight now proves those
  lifecycle requirements before every container start.
- Exact shared routing preserved the existing Yandex Mail OAuth/MCP paths,
  returned 404 for unmatched canaries, and left Amnezia as the sole owner of
  host port 443. Public HTTPS 443 terminates at ngrok; the VPS gateway remains
  loopback-only on 8443.

## Evidence still required before final release

- The first native `windows-latest` routed conformance and package run. No live
  Windows-to-ChatGPT walkthrough is claimed because a Windows workstation is
  unavailable; that walkthrough remains explicitly deferred.
- Abrupt power-loss, interrupted activation, matched rollback, certificate
  renewal, and an external VPN data-plane check. The clean reboot and external
  SSH/Yandex route checks have passed. Docker and Amnezia must not be restarted
  or reconfigured as a shortcut.
- Human `gh auth login` inside the VPS workload and a private
  clone/fetch/commit/push proof.
- Signed +5-minute, +1-hour, +24-hour, and +7-day operator checks with no
  privacy, containment, routing, certificate, storage, latency, SSH, VPN,
  Docker, or Amnezia rollback signal. Seven days is the final release gate.

Until those items pass, artifacts are development candidates and must not be
described as a completed production release.
